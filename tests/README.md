# Тесты диагностики core

Запуск с checkout подходящей версии зависимости `hev-task-system`:

```sh
tests/run-diagnostics.sh /path/to/hev-task-system
```

Нужны C-компилятор, make и ripgrep. Скрипт копирует runtime во временный каталог,
собирает статическую библиотеку и компилирует настоящие исходники core с
`-Wall -Wextra -Werror`. Исключения для существующего кода:
`-Wno-unused-parameter -Wno-sign-compare`. Переданный runtime и родительский
checkout tunnel не меняются. `KEEP_BUILD=1` сохраняет сборку и собранный лог.

Один набор тестов поддерживает старый UDP API с отдельными датаграммами и новый
API с пакетной обработкой. Используются настоящие задачи runtime и локальные
сокеты. Для воспроизводимого отказа platform binder подменяется только его
callback.

Проверяется:

- Успешный handshake в обычном и pipeline-режиме; обычная передача UDP.
- Сохранение IPv4/IPv6 назначения после передачи владения адресом в handshake.
- Отказ соединения с proxy, исходный errno, все SOCKS5 reply-коды и неизвестный код.
- Отказ аутентификации и неполные заголовки/адреса ответа.
- Реальное истечение ожидания, отмена до/во время ожидания, подавление повторной ошибки.
- UDP association без конечного адреса, отказ binder, неверный адрес, ошибка чтения
  и EOF управляющего канала; отсутствие INFO на каждом обычном UDP-пакете.
- Ограниченная длина diagnostic target и отсутствие credentials в INFO.

Тесты выполняются на платформе хоста и не заменяют проверки на Android/iOS.
Реализация platform binder здесь не проверяется. Для отказа соединения тест
закрывает временный локальный сокет перед подключением к его адресу;
внешняя сеть не нужна.

Регрессии ревью запускаются этой же командой автоматически. Отдельную группу
можно выбрать через `REGRESSION=partial-reset`, `tcp-splice`, `empty-udp`,
`udp-splice` или `udp-progress` перед командой запуска.

Дополнительно проверяются короткий ответ каждого этапа handshake с последующим
настоящим TCP RST, timeout/EOF/cancel полного core TCP splice, timeout/cancel core
UDP splice и восстановление после принятого частичного UDP batch. На macOS
Unix datagram buffer при заполнении выдаёт `ENOBUFS`, поэтому timeout отправки
batch воспроизводится на реальном stream buffer; чтение частичного batch
проверяется через настоящий UDP-in-TCP framing.

Android: ошибка одного UDP-send (`EMSGSIZE`) не завершает ассоциацию и не скрывает
последующий control EOF; terminal syscall-ошибка core splicer остаётся в истории.
Прямой Android UDP API при timeout возвращает `-2` без INFO: вызывающий слой ещё
решает, живо ли второе направление. Терминальный timeout проверяется на границе
splicer. В iOS прямой mmsg timeout терминален и логируется. Пустая датаграмма
Android получает причину неверной длины; iOS сохраняет штатный молчаливый drop и
не подавляет последующую причину закрытия ассоциации.
